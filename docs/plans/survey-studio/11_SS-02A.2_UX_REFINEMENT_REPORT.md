## 1. What changed

### 1.1 A simpler default question card
The card now shows, by default, only what the owner listed:

| On the card | Where the rest went |
|---|---|
| Number and answer type (quiet, one line) | — |
| Question text (larger, the visual anchor) | — |
| The routing choice ("Everybody continues" / "Different next questions" / "Follow-ups for each answer") | — |
| Each answer with where it leads, right-aligned in one column | The answer's **stable code**, exclusivity, interruption rule, "Other" text rule and Remove are in the answer's **More** menu |
| One "+" between cards to insert a question | Creating a question from inside a destination picker is unchanged |
| A concise status in the header — "2 to fix" — only when something is wrong | The full list is behind it and behind **Next issue** |
| **Mandatory-escalation badge ("Must escalate") — always visible** | — |
| "Shared · used in n places" when the question is shared (it changes what can be edited) | "Draft question", version, wording version and approval, selection limits and the free-text length rule are in **Details** (ⓘ on the card) |

Removed from the default view: the "Draft question" tag, the "Wording v1 · not approved" tag on every card, the stable
code on every answer row, the always-open "Other" settings strip, the free-text rule controls, the tinted answer rows,
and the boxed two-column follow-up panel.

### 1.2 Compact interruption authoring
- Each interrupting answer carries a short badge on its row: **"Stops · Escalate"**, **"Asked first, then
  continues"**, **"Stops · goes to Q5 …"**, and its governing class — **"Must escalate"** or "May interrupt".
- The detailed policy (the three governed behaviours and the one detail each needs) opens **for one answer at a
  time**, under that answer, through a **Rule** control on the row. Opening another closes the first. Setting a
  behaviour from the answer's picker opens that answer's rule automatically, so nothing takes more steps than before.
- Anything undecided is flagged on the row even while the rule is closed ("Choose the outcome", "Asked first · choose
  the question", "Stops · goes to … choose").
- Governance and execution are unchanged: the definition decides what a placement may choose; a mandatory escalation
  offers only escalations, shows the other behaviours as unavailable, and wins when selected with anything else.
- "Try a combination" is now a disclosure (closed by default) under the follow-up order.

### 1.3 Visual hierarchy
From a review of the SS-02A.1 screenshots: one type size carries the question (19 px), answers are 14 px, everything
else is 11–12 px and muted; answer rows are separated by hairlines instead of tinted boxes; destinations align in a
single right-hand column; card padding increased; number chip and row controls quietened; lanes thinner; the builder
column slightly narrower for a better line length. Lego module cards in the composer are unchanged apart from their
warning outline. No inspector was added; nothing became a multi-panel layout.

### 1.4 Entry-condition drawer: an accessible modal
| Behaviour | Implementation |
|---|---|
| Background blocked | A dimming backdrop covers the page; every part of Survey Studio outside the drawer is `inert` (no pointer, no focus, hidden from assistive technology); clicking the backdrop closes |
| Focus containment | Tab and Shift+Tab cycle inside the drawer |
| Escape | Closes the drawer; inside an open menu it closes only the menu |
| Focus restoration | Focus returns to the control that opened the drawer, on Apply, Cancel, Close, backdrop and Escape |
| Accessible naming | `role="dialog"`, `aria-modal="true"`, named by its heading, described by its subtitle |

This closes keyboard finding **K4** from SS-02A.1.

### 1.5 Validation states told apart
The single green "No open issues" is gone. The bar shows **"n to fix"** (amber) or **"Routing complete"** (neutral,
not green, and it does not say "ready"). It opens **Readiness**, with three separate lines:

| Line | Example |
|---|---|
| **Routing structure** | "Complete: every answer leads somewhere and every path ends." / "2 to fix — listed below." |
| **Wording approval** | "8 of 8 questions use wording that is not approved." |
| **Ready to publish** | "**No.** Wording is not approved. This is a prototype: nothing can be submitted, approved or published from it." |

Wording approval for one question is in its Details. "Prototype · not saved" is unchanged.

### 1.6 Small fix
Short codes such as "ILP" are no longer shown as "Ilp" in the drawer's value lists.

### Files
Changed, all inside the prototype: `BuilderPage.tsx`, `StudioRoot.tsx`, `ComposerPage.tsx`, `EntryRuleDrawer.tsx`,
`ui.tsx` (modal drawer), `model/flow.ts` (a read-only `wordingStatus` count), `styles/survey-studio.css`, and the two
prototype journey files. No model, operation or evaluator rule changed.

## 3. Interaction cost: before and after

Counted as discrete actions (a click or key activation; typing a text counts once).

| Common authoring task | SS-02A.1 | SS-02A.2 |
|---|---:|---:|
| Insert a question on a route and name it | 3 | 3 |
| Give a Yes/No question two different routes | 3 | 3 |
| Add five answer options | 5 | 5 |
| Route one answer to a destination | 2 | 2 |
| Route an answer to a brand-new question | 2 | 2 |
| Add "Other — please specify" | 1 | 1 |
| Duplicate an answer | 1 | 1 |
| Reorder an answer | 1 | 1 |
| Add a follow-up question for a selected answer | 2 | 2 |
| Set an interruption behaviour and its detail | 3 | 3 (its rule opens by itself) |
| Reorder follow-ups | 1 | 1 |
| Open and apply an entry condition | unchanged | unchanged |
| Undo / redo | 1 | 1 |

Deliberately **one step further away** (progressive disclosure), none of them part of ordinary authoring:

| Now behind one extra step | Where |
|---|---|
| Looking at a *second* answer's interruption rule | **Rule** on that answer |
| "Try a combination" preview | its disclosure |
| A question's version, wording approval, selection limits | **Details** |
| Changing the free-text length rule | **Details** |
| Changing the "Other" text rule (adding Other is still one step) | the answer's **More** menu |
| An answer's stable code | the answer's **More** menu |

## 4. UX assessment

| Owner's requirement | Assessment |
|---|---|
| Default card focuses on text, type, options, destinations, one insertion control, concise status | Met — see U3, U4 |
| Advanced settings progressively disclosed | Met — Details, More, Rule, Try |
| Mandatory-escalation indicators never hidden | Met — the "Must escalate" badge is on the row in every state; tested with all rules closed |
| Normal and exceptional paths understandable at a glance | Improved: destinations form one column; exceptional answers stand out by badge and red-outlined pill; lanes say where they rejoin. **For the owner to judge** |
| Compact interruption authoring; expand one answer's policy at a time | Met — U5, U6 |
| Governance and execution semantics preserved | Met — same operations, validation and unit tests as SS-02A.1, all passing |
| Typography, spacing, alignment, hierarchy, canvas balance | Reworked as in §1.3. **For the owner to judge** |
| No oversized inspector or cramped multi-panel layout | Met — none added |
| No loss for keyboard users | Met — keyboard-only journey passes unchanged; the drawer is now properly contained |
| Drawer: modal, focus containment, Escape, restoration, naming, keyboard-tested | Met — §1.4 |
| Routing validity vs wording approval vs publication readiness | Met — §1.5; no generic green "ready" |
| "Prototype · not saved" retained | Met |

### Remaining gaps and honest limits
| # | Item |
|---|---|
| 1 | The follow-up order list repeats what the answer rows already say ("asks Q2.1 …"). It is kept because it is the ordering control; with one follow-up it adds little |
| 2 | Details shows the multi-select selection limits but they cannot be edited yet (SS-02A gap G10) |
| 3 | At 1440 px the answer text and its destination sit far apart on short answers; the eye follows the hairline. A hover highlight could help; none was added, to keep rows calm |
| 4 | Row controls (Duplicate, More) are quiet by design. Their discoverability for first-time users is untested |
| 5 | The readiness lines are computed in the browser. Real readiness is the server's judgement on a saved revision |
| 6 | Keyboard finding K5 (no question outline in long modules) is still open; planned with the graph work |
| 7 | No screen-reader session has been run. The drawer's semantics are correct by inspection and automated scan only |
| 8 | Display numbers (Q2, Q1a) still change when routes change |
| 9 | Composer and Home were reviewed and left as they were, apart from the status wording; say if they should be refined too |
| 10 | Moderated usability testing and design sign-off remain the owner's |

## 5. For the owner's review

The prototype is running with the setting on; reload to pick up the changes. Suggested look:
1. Open a module and compare a Yes/No card, a five-option card and a multiple-choice card with follow-ups.
2. On an interrupting answer press **Rule**; then **Rule** on another.
3. Press ⓘ **Details** on a card, and **More** on an answer.
4. Click a module's "Runs…" chip: try Tab, Shift+Tab, Escape, and clicking outside.
5. Click **Routing complete** (or "n to fix") in the bar.
