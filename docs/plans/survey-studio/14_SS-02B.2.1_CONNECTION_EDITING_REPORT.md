## 1. What changed

### 1.1 Select and delete a connection
- Every connection is now **its own selectable line**. Two answers that lead to one question are two routes (they
  were drawn as one merged line in SS-02B.2), so each can be edited alone.
- Clicking a line **selects and highlights** it and opens a **small toolbar beside it**: the route's name
  ("Q1 · Yes → Q2"), **Change destination** and **Disconnect route**.
- **Delete** or **Backspace** disconnects the selected route — never while a text field has focus. **Escape** or a
  click on the canvas deselects.
- Disconnecting removes the routing binding **from the canonical draft model** (the same operation as Guided's "Leave
  undecided for now"). The source step, the answer option and the former destination all remain. There is no
  confirmation dialog: it is an ordinary draft edit and it can be undone.

### 1.2 Redraw connections
- Drag from the **route's own handle** (each answer, each decision result, each rule, "Otherwise", "After the
  follow-ups", each module outcome has a named handle on its row) onto any card or outcome.
- **Change destination** in the toolbar picks the destination from a searchable list, without disconnecting first.
- An existing route can be re-pointed by **dragging its far end** onto another card.

| Kind of route | Select | Disconnect | Redraw / re-point |
|---|---|---|---|
| Yes and No | ✔ | ✔ | ✔ |
| Single-choice, per option | ✔ | ✔ | ✔ |
| Multi-select: "Everybody", "After the follow-ups", each prioritised rule, "Otherwise" | ✔ | ✔ | ✔ |
| Decision: Matches, Otherwise, Unknown | ✔ | ✔ (Unknown becomes undecided, never "otherwise") | ✔ |
| To a module outcome | ✔ | ✔ | ✔ |
| Survey level: a module outcome to a module or an end of call | ✔ | ✔ | ✔ |

### 1.3 Incomplete connections are shown, not hidden
After a disconnect the source card stays; its row reads **"Choose destination"**; a **short dashed line ending in
"?"** leaves the handle; the card carries an issue count; the top bar reads "n to fix" instead of "Routing complete";
**Next issue** selects the step (in the graph as well as in Guided); and Readiness says the draft is not ready to
publish. Guided shows the same route as "Choose destination · Not routed yet".

### 1.4 Governed restrictions are kept
| Attempt | Result |
|---|---|
| Re-point a mandatory escalation to anything but an approved escalation outcome (by drag, by endpoint drag, or from the toolbar) | Refused with the reason; the toolbar's list offers only the approved escalation outcome. It may be disconnected — the draft is then incomplete — but cannot be redrawn elsewhere |
| Disconnect or re-point a survey's "Review required" halt | Refused: "Review required is governed…". The toolbar shows the explanation and no Disconnect button |
| A survey route to an earlier module | Refused: "A route may only go to a later module" |
| A follow-up question as a destination; "Review required" as an ordinary destination; a step to itself | Refused with the reason |

Every refusal leaves the model fingerprint unchanged.

**Lines that show structure, not routes.** Some lines are a picture of a canonical structure and are not
independently deletable. Selecting one says so and offers the semantic edit instead:

| Line | What the toolbar says | Semantic edit offered |
|---|---|---|
| The order of a follow-up queue ("1 · if …", "2 · if …") | "The order in which follow-up questions are asked. It is not a route of its own…" | **Edit on Q…** — opens the owning question, where the order and each answer's follow-up are set |
| "then rejoins" at the end of a queue | It is the owning question's "After the follow-ups" route | Edit on the owning question (that route's own handle can be disconnected and redrawn) |
| An interrupting answer's stop route | Part of the answer's interruption rule | Edit on the question |
| "Module starts" / "Start of call" | Where it starts follows the first step / the module order | Add a step before it; reorder modules |
| A folded branch's line | A folded branch | Open it |

### 1.5 One model
- Selection, the toolbar and the highlight are view state. **No edge list is kept or edited**: the lines are derived
  from the canonical model on every render, exactly as before.
- Disconnect and reconnect dispatch to the operations Guided and the Composer already use (`setEdge`, `setRejoin`,
  `setFallback`, `updateRule`, `setDecisionUnknown`, `setRoute`). One addition: `setDecisionUnknown` accepts
  "undecided" so a decision's Unknown route can be left open like every other route; Guided's Unknown picker gained
  the same "Leave undecided for now".
- A route's identity is its source step and route key (`n1` + `YES`); both are stable across a disconnect and
  reconnect. The record that carries a reconnected route is a new record; Undo restores the original record exactly.

### 1.6 Keyboard
Tab reaches each line (it announces "Route: Q1a · After the answer → Q2. Press Enter for route actions."). Enter
selects it and moves focus to the toolbar's first action; Enter opens the destination list (type, Enter). Tab to
**Disconnect route**, or press Delete. After either, focus is on the **source card**; Enter opens that card's routes,
where the destination is chosen. No dragging is needed at any point.

## 4. Gaps and honest limits

| # | Item |
|---|---|
| 1 | Two routes from one card to the same destination overlap for most of their length. Each is selectable near its own handle, and the toolbar names the one selected, but picking the intended one where they overlap takes care |
| 2 | Dragging a line's far end re-points it; dragging its **start** to another answer is not supported (a route belongs to its answer) |
| 3 | A new step still cannot be created by dropping a connection on empty canvas |
| 4 | A long line can pass behind a card; it is selectable only where visible |
| 5 | Tab reaches every line, so a large module has many stops. The outline remains the faster keyboard path to a step, and a step's routes are all editable in its panel |
| 6 | The toolbar is positioned beside the middle of the line and kept inside the canvas; on a very long line that point can be far from both ends |
| 7 | No screen-reader session has been run; labels and focus order are verified by inspection, automated scan and keyboard journey only |
| 8 | SS-02B.2 gaps 1, 3–14 (report `13` §7) still apply; its gap 2 is unchanged ("+" only on bottom routes) |
| 9 | Moderated usability testing and formal UX sign-off remain the owner's |

SS-02B.2 design decision **G-6** ("several answers to one destination are one edge") is **withdrawn**: each route is
now its own line.
