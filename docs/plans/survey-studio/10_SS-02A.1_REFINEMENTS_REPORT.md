## 2. What was built

### R1 Governed interruption controls
- **On the answer (definition):** each answer's **More** menu has "Can this answer interrupt?" — *Ordinary answer*,
  *May interrupt follow-ups*, *Must escalate*. It is editable only on a draft question; on a shared question it is
  fixed and shown as a tag ("Must escalate").
- **On the placement:** when an answer interrupts, an **Interruptions** block appears under the question with one
  card per interrupting answer: its governing class, the three behaviours as plain-language choices, and one detail —
  *End the module with* (an outcome other than Completed) · *Ask first* (a question, after which the remaining
  follow-ups continue) · *Continue at* (a chosen destination).
- **Mandatory escalation:** the answer's picker offers only "Stop and escalate: …". On its card the other two
  behaviours are shown struck through with "Not available: this answer is a mandatory escalation, and a placement
  cannot weaken it"; activating them does nothing. It is also enforced outside follow-up mode: "everybody continues"
  is a blocker, and with per-answer routes its destination may only be an escalation outcome.
- **Precedence when several interrupting answers are selected:** a mandatory escalation first, whatever else was
  selected; then stop-and-escalate, stop-and-go, handle-and-resume; ties by answer order. The preview states which
  one applied and what was not asked.
- **Progressive disclosure:** a question with no interrupting answer shows none of this.

### R2 Create Blank Module
"Create a blank module" in the composer's "Add a module here" picker (created, placed there and opened), "New
module" on the library shelf (placed at the end), and "New module" on Home › Library › Modules (standalone, listed
under "Your draft modules"). One inline form: name, kind, optional purpose. The module is marked **"Draft · not in the
shared library"** everywhere and opens on "Add the first question". Creating and placing is one undoable step.

### R3 Duplicate and reorder answer options
- **Duplicate** button on every answer row: the copy appears directly below, named "… (copy)" with the text focused
  for renaming, a **new stable code** (`CASH_COPY`, then `CASH_COPY_2`; never reused), exclusivity and interruption
  class copied. **Routing is not copied:** with per-answer routes the copy shows "Choose destination" and "Not routed
  yet — choose a destination"; in a follow-up plan it is undeclared. The acknowledgement reads "Duplicated 'Cash' —
  choose where the copy leads". The original and its routes are unchanged.
- **Reorder** by a drag handle on the row (pointer and keyboard), **Alt+↑ / Alt+↓** in the answer text, or Move up /
  Move down in the More menu. Focus follows the moved row. "Other — please specify" stays last and cannot be
  duplicated.
- **Design change made during testing:** the per-row tools used to appear on hover or focus. That changed the row's
  height as focus moved, and a click on something below could miss. Each row now has two always-present controls —
  Duplicate and **More** (order, exclusive, interruption rule, remove, and the stable code) — so the layout never
  shifts and the card is simpler.

### R4 Unresolved branches obvious, folded or not
| Place | Signal |
|---|---|
| Question card with a problem | Amber left edge and border, whether folded or not |
| **Folded** question | Names what is undecided: "Not decided: No → ? · Other → ?"; clicking it unfolds the card |
| **Collapsed** lane | Amber dashed lane line; "1 to fix — Q1a does not lead anywhere" in the header |
| A branch that ends nowhere | "does not lead anywhere yet" in the lane header and "This branch stops here — choose where it leads" at its end |
| Broken normal path | Dashed amber connector and the amber end marker |
| Follow-up designer | Undeclared answers listed in "Order of follow-ups" as "not decided yet" |
| Module card in the composer | Amber outline plus the existing "n to fix inside" tag and dashed outcome pill |
| Top bar | **Next issue** button (and **F8**): goes to each problem in turn, opening any folded lane or card on the way |

### R5 Responsive desktop layout
Below 1200 px the library shelf is an overlay opened by "Module library", so the canvas keeps its width; the
follow-up designer and the interruption choices stack; the bar tightens; destination pills truncate (full text on
hover); the answer's stable code moves into its More menu so the label keeps its room. Verified at 1440, 1280 and
1024 (§3.3).

### R6 Keyboard-only authoring
A scripted journey with **no mouse action after sign-in** (§4).

### R7 "Prototype · not saved"
The tag stays on every screen, with a tooltip and an explanation headed "This is a prototype — nothing is saved".
Wording that could suggest persistence was removed: "Saved condition" → "Library condition"; "Also save it to the
library" → "Also add it to the reusable library (Prototype: held in memory, not saved)"; the acknowledgement "Saved
the condition…" → "Added the condition… to the library". No saving, saved, offline or conflict state is shown or
simulated. A test reloads the page and confirms the workspace is back to the sample library and says so.

## 4. Keyboard-only testing

**Journey (keys only, after sign-in):** skip link → Create survey → name, Enter → add three modules by search →
reorder by keyboard drag and by the move button → F8 to the first issue → route two outcomes through the picker →
open the entry-rule drawer, change the missing-information choice, Apply → open a module → Edit a copy → add a Yes/No
question on a route, type it → switch to per-answer routes → choose a destination by search → add a single-choice
question → three options by typing → route two → duplicate one → rename → Alt+↑ → route the copy → Undo / Redo by
button and by shortcut.

### Key map
| Action | Keys |
|---|---|
| Move between controls | Tab / Shift+Tab |
| Activate a button, link or menu item | Enter (or Space) |
| Skip the application navigation | Tab, Enter on "Skip to content" |
| Search a picker; choose | type; ↑ ↓ ; Enter |
| Close the top-most menu, picker or drawer | Esc |
| Reorder a module, an answer or a follow-up by drag | Space on its handle, ↑ ↓, Space to drop |
| Reorder an answer while editing its text | Alt+↑ / Alt+↓ |
| Commit a question or answer text | Enter (or move away) |
| Add an answer option | type in "Add another option", Enter (focus stays for the next) |
| Choose within a set of options (e.g. missing-information choice) | ↑ ↓ (the set is one tab stop) |
| Next thing to fix | F8 |
| Undo / Redo | Ctrl/⌘+Z, Ctrl/⌘+Shift+Z (when not typing in a field), or the buttons |

### Findings
| # | Finding | Severity | Outcome |
|---|---|---|---|
| K1 | Per-row tools appeared on focus and disappeared on blur, changing row height; a click below could land on a different element and be lost | High (affected mouse users too) | **Fixed** — always-present Duplicate and More controls |
| K2 | Focus after inserting a question goes straight into its text; after a menu or picker closes it returns to the control that opened it; after a reorder it follows the moved row | — | Confirmed working |
| K3 | A radio group is one tab stop, moved with arrow keys. Correct behaviour, but the first test assumed otherwise | Info | Documented in the key map |
| K4 | The entry-rule drawer takes focus when opened and closes with Esc, but does **not** trap focus: Tab can move to the page behind it | Medium | **Open** — decide in SS-02B whether the drawer should be modal for keyboard users |
| K5 | In a long module there are many tab stops between questions. F8 jumps between problems, but there is no "jump to question" or outline | Medium | **Open** — an outline is planned with the graph work (SS-02B) |
| K6 | Undo/redo shortcuts are deliberately ignored while typing in a field (so the field's own undo works); this is not announced anywhere | Low | **Open** — add to on-screen help |
| K7 | Not tested: a screen reader. Names and roles pass the automated scan, but announcement quality needs a person with assistive technology | — | **Open** — owner-arranged |

## 6. For the owner's UX review

The prototype is running with the setting on. Suggested path through the refinements:
1. Home → Library → **New module**, or in a survey: "Add a module here" → **Create a blank module**.
2. Add a single-choice question, type five options, choose "Different next questions", press **Duplicate** on one.
3. Collapse a branch that is not finished; press **Next issue**.
4. Add a multiple-choice question; in an answer's **More** menu set "May interrupt" on one and "Must escalate" on
   another; choose "Follow-ups for each answer"; try the three behaviours and "Try a combination".
5. Narrow the window to about 1024 px.
6. Put the mouse aside and repeat step 2 with the keyboard.
