## S1-B as built (2026-11-17)

- **Requirements addressed:** APP-007 (the same session moves live → final without duplication and appears in Call
  Explorer attempt counts and Call Detail), VOICE-004 (end, network failure, tab close and reconnect; no orphaned open
  session), VOICE-005 (provider and model metadata linked by session), VOICE-006 (client and server events with
  de-duplication: a replayed event never acts twice), EVD-002 (ordered, timestamped ledger with actor and source).
- **Model reuse:** one browser test session = one `contact_attempt` (transport BROWSER, record origin CALL360_RUNTIME,
  INITIATED → IN_SESSION → ENDED, or FAILED if never connected) and, on connection, one `conversation_session` whose
  pins (published script + manifest, FINAL risk assessment + hash, latest fact snapshot + hash, contacted party,
  masked contact) are enforced by the existing guard. States used: CREATED (live), INTERRUPTED (resumable 30 s),
  FINALIZING, FINALIZED, ABORTED. `media_status = NOT_REQUIRED`, `transcript_status = UNAVAILABLE`. Case timeline:
  `VOICE_SESSION_STARTED` / `VOICE_SESSION_ENDED` in `case_event`.
- **One migration:** `0012_session_event` — insert-only ledger (server `seq` per attempt; source SERVER/CLIENT/SYSTEM;
  client event ID unique per attempt; client sequence and time; `out_of_order`; metadata-only `details`). The
  approved schema had no session event store, which EVD-002 requires. No audio, transcript or microphone content.
- **APIs:** `POST /voice/sessions` (persists), `POST /voice/sessions/{id}/resume` (owner; interrupted within 30 s or
  not yet connected), `POST /voice/sessions/{id}/stop` (owner; idempotent; also ends a live connection),
  `GET /voice/sessions/{id}` and `GET /voice/sessions?case_id=` (`case.read`, Singapore scope). Recovery: at startup
  every open session is finalised (`BACKEND_RESTART`); a 15 s sweeper finalises never-connected (90 s), interrupted
  beyond 30 s (`ABANDONED`) and live-without-connection (`ORPHANED`) sessions.
- **Frontend:** Voice Studio shows the persisted record and event timeline (live refresh), a resume offer after a
  refresh, automatic resume after a network drop (3 tries), clear final and failure messages, and the case's session
  history; Call Detail labels browser attempts and shows their persisted timeline; leaving the page stops the session;
  closing or reloading the tab leaves it resumable, then abandoned.
- **Verification:** backend 325 (6 S1-B: Start → Stop persistence with pins and gap-free order, repeated Stop,
  network loss → resume → abandonment, never-connected and backend-restart recovery with no orphan left, duplicate
  and out-of-order client events, idle timeout and live REST stop, ownership, scope and CSRF); frontend 86 unit;
  Playwright 20 (S1-B: refresh after Stop, mid-session refresh → resume of the same session, Call Detail history and
  timeline, tab closure → interrupted → abandoned). Chrome demonstration with a real backend restart:
  `evidence/S1-B/chrome_demo.txt`. Development seed digest unchanged; audit chain verified.
- **Fixed while verifying:** a deferred cleanup could close a just-opened connection during React's development
  double-mount (fast Start); the stored record did not refresh once a session ended; closing a tab was misread as
  microphone loss; a repeated Stop on a finished session appended a stop request.

## S1-B known limitations

- Live connections and pending credentials are per process; after a restart, sessions are finalised, not resumed.
- Resume needs the same signed-in user within 30 s; a refresh needs the microphone permission again.
- Client clock values are stored as reported (not trusted for ordering; the server sequence is authoritative).
- Runtime attempts count in operational attempt metrics like any other attempt (they are synthetic test sessions).
