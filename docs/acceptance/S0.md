- **CP0.6-F1 (resolved 2026-11-17):** operational audit view scoped to Singapore; full ledger retained (see CP0.6 section).
- **SEC-008 (PENDING, owner decision 2026-11-17):** requirement-level ASVS 5.0 review by the designated security reviewer; handoff `docs/security/SEC-008_REVIEW_HANDOFF.md`. Not self-certified.
- Residual risks RR-01…RR-10 (`THREAT_MODEL_S0.md` §4).
- Security defaults S-2…S-14 pending security-owner approval.
- Approver names (C-20).
- `CLAUDE.md` terminology outside specs (C-24).
- Business assumptions DEC-001…028.
- **D-43 One-time password flag** (CP0.1B-3, 2026-11-17): the approved identity design requires administrator-set passwords to be changed at first sign-in, which the CP0.1A schema could not record. Migration `0010_password_change_required` adds `local_credential.must_change_password` (boolean, default false). While it is set, the account may sign in, read `/me`, read its session and change its password; every permission-protected endpoint returns `403 PASSWORD_CHANGE_REQUIRED`.
- **D-42 CP0.4b portal first** (owner, 2026-11-16): CP0.4b delivers the Manual Intake portal first (Data Intake screen at `/intake`, ADMIN) on the CP0.4a APIs plus a read-only reference endpoint API-087 `GET /intake/reference` (`intake.read`, market-scoped); mock upstream, scheduling, corrections, saved drafts and Admin Integrations stay deferred.
- **D-41 CP0.4 split and intake rules** (owner, 2026-11-16): CP0.4 is delivered as CP0.4a (manual API intake: preview, validation, idempotent submission, policy/sale/party persistence, callback case, holds, portal integration) and CP0.4b (mock upstream, field corrections, Data Intake screen, Admin Integrations, import scheduling). Callback `due_at` (timezone-aware; may be past; not before the sale) and `priority` (1–5) are supplied by the source transaction; nothing is scheduled or prioritised by Call360. A new sale attaches to an existing Singapore policy only when the identifiers and material policy fields match; conflicts return 409; historical facts are never overwritten; parties are never merged on name or telephone number.
- **D-40 Vertical slices** (owner, 2026-11-15): CP0.3 and CP0.5 are delivered as slices F1–F5, with F0 as the reduced CP0.1B-2; CP0.4 follows (S0_IMPLEMENTATION_PLAN).
- **D-39 Singapore-only Stage 0 scope** (owner, 2026-11-15, at CP0.2 acceptance). All business functionality is Singapore-only. `market_code` is retained in the schema for extensibility. Effective scope = mapped markets ∩ **enabled markets `{SG}`**, so every principal, ADMIN included, sees only `SG` records; `MY` synthetic fixtures stay in the database and are never exposed (list, count, facet, search suggestion or by-ID lookup → `404` + `ACCESS.DENIED_OBJECT`). No multi-country market-permission administration is built in S0. The master BRD and register are unchanged. Recorded in `CP0.2.md` §1.
